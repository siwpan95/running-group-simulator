## 架构方案（基于现有实现，不推倒重来）

- **裁决内核抽象**（`core/rules/`）：`SystemProfile` 接口 = 检定 / 伤害 / 部位 /
  穿透 / 主动防御 / 休克。GURPS 现有逻辑重构为参考实现（`core/rules/gurps.py`），
  行为零变化，既有测试全绿作重构安全网。
- **系统注册表**：`core/rules/__init__.py`（代码注册）+ `config/systems.json`
  （元信息声明，`default_system`）。module.json `meta.systems: ["gurps", "coc7"]`
  声明可用系统（`compatible_core` 保留向后兼容）。
- **ResolutionPacket 加 `system` 字段**；ViewModel（锚点叙事）与 View（终端渲染）
  保持系统无关。三层红线不动、模组=JSON 数据包原则不动。

## 数据管线（不借鉴 RolePlayer，独立设计）

- 内容目录 = **人工策展 JSON**：从资源库文本逐条提取（字段+来源引用），
  每字段写测试钉住；脚本只做候选抽取/去重辅助，不做黑盒批量导入。
- 版权口径：ORC/CC/OGL 合法内容优先；版权不明社区翻译只作取材参考、不直接复制进仓。

## 边界（2026-09-02 review 拍板）

- **不做**：载具系统、无限世界世设、3e 扩展世设全量落地（只做素材包索引）；
  GURPS 自身规则不再深化。
- 每个系统 = 核心裁决 + 最常用目录（技能+怪物+法术/理智）+ 一个示例模组，
  不追求全量条目。

## 验收（每阶段）

新 profile 测试套件（固定种子）+ 既有套件全绿 + 示例模组端到端冒烟 +
README/CHANGELOG 记账 + 推送前逐项确认。
